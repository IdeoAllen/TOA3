## 0. 一句话

**TOA 内嵌的是「套件自管的一份 DSH 运行时」**：目录、端口、密钥、启停、卸载与本机其它 DSH（含 WorkBuddy）默认隔离；用户日常只走**四步开用**；系统设置路径项仅排障。双版本 = **官方精简 / 预制必备** 两条 CDN 预制包，不是两套互不相干的产品。

### 0.1 最低门槛（主理人 · 待专家组论证）

> **个人不成熟想法，请专家组论证后拍板或改写。**

**改版后的 Harness 在 TOA 内必须「能用」，并足以支撑排错与日常开发；不能把 WorkBuddy / 其它三方 Agent 当成排错刚需。**

| 层级 | 要求 | 若做不到 |
|------|------|----------|
| **底线** | 上游升级合入后，TOA 内嵌实例可稳定：四步装起 → 启停 → 内嵌对话/改文件主路径通 | **禁止**宣布整改完成；不得依赖「去开 WorkBuddy 才能查」 |
| **排错面** | Host 自读日志 → 一键修复人话、快照回退、安装/会话目录、重启注 Key | 禁止把「请打开启动日志」当用户主路径；研发才下钻日志 |
| **隔离** | 排错在 `~/.toa3/harness-runtime` 内完成；WorkBuddy 仅允许「借 Node/bin」级回落，**不是**官方排错入口 | 禁止文档/话术引导用户「先装 WorkBuddy 再修 TOA」 |

**论证焦点**：底线是否写成发布门禁（合入 checklist 必过项）？排错是否还要加「一键打包诊断包」？三方 Agent 是否允许出现在「高级回落」文案中（建议默认**不出现**）？

## 1. 目标与非目标

### 1.1 目标（整改后须可验收）

| # | 目标 | 可测标准 |
|---|------|----------|
| **G0** | **改版可自用自排错** | 合入新上游后：TOA 内嵌主路径可用；常见故障用 Host 日志/修复/快照可闭环；**不依赖** WorkBuddy 等三方 Agent 才能干活或排错 |
| G1 | 小白无感就绪 | 干净机：选版本 → 可预期进度 → 一次 Key → 启动 → 内嵌可用；不出现 Node/npm/路径功课 |
| G2 | 双版本语义清晰 | 官方 = 仅核心 Web；预制 = 核心 + 白名单插件；装错可改装，互斥覆盖安装树、默认可留会话 |
| G3 | 全生命周期闭环 | 装 / 启 / 停 / 重启 / 修 / 快照回退 / 卸 / 日志 / 目录 均可在编码智能体页完成 |
| G4 | 与本机 DSH 共存 | 不写对方 home；不默认杀对方进程；卸载不扫盘删客户其它 DSH |
| G5 | 发版可运营 | 预制 zip 走 CDN；主安装器不塞几百 MB；URL/sha256/版本可运营更新 |
| G6 | 上游升级可整改 | DSH 大版本升级后有钉扎、denylist、预制重建、回滚与点验清单 |
| **G7** | **状态衔接可靠 · 不影响用户应用** | 官方/预制 × 已装/未装 × 已启/未启 × 可升级 正交态清晰；切换不抢口、不静默大包、不抹会话；弱提示不得阻断启停 |

### 1.2 非目标（明确不做）

- 山寨第二套 Agent 聊天 UI 替代 `dsh web`
- 引擎管家 / Hub 半残壳（ARCH-09 D Hold）
- 把客户本机已有 DSH「接管」为默认路径（高级可选且须二次确认——默认关闭）
- **以 WorkBuddy / 其它三方 Agent 作为官方排错或「能用」前提**（借二进制仅属降级回落，不得写进主路径话术）
- 主安装器内嵌完整 `node_modules` 树
- 费用中枢、插件应用商店式收录（ARCH-09 否决项）

## 2. 产品模型：一份运行时 · 两种口味

```
┌──────────────── TOA Host（编码智能体页）────────────────┐
│  四步开用 / 启停修卸 / 投喂 / 日志 / 快照                 │
│  surface: 默认内嵌；外开自点；能力不及提示「浏览器打开效果更佳」 │
└──────────────────────────┬──────────────────────────────┘
                           │ spawn + DSH_HOME
                           ▼
┌──────────────── Guest：正版 dsh web ────────────────────┐
│  http://127.0.0.1:3082/?token=…                         │
│  会话 / 工作区 / 插件市场（仅预制白名单预装）              │
└─────────────────────────────────────────────────────────┘

落盘（唯一默认）：
  ~/.toa3/harness-runtime/
    node/                         # 便携 Node（预制包；须 ≥22.15，含 createZstdCompress；见 harness_runtime_heal）
    node_modules/@deepseek-ai/dsh/
    .dsh/                         # DSH_HOME：凭据、会话、web profile
    MANIFEST.json                 # flavor / version / plugins
```

| 口味 `flavor` | 用户文案 | 包内容差异 | 适合 |
|---------------|----------|------------|------|
| `official` | 安装官方版 | 便携 Node + dsh + **仅** `dsh-base` / `dsh-web-app` | 要干净、体积更小 |
| `prefab` | 安装预制版 | 同上 + `prefab_essential_plugins` 白名单（禁 boot-killer） | 日常推荐 |

**Node 下限（2026-09-24）**：会话持久化 `dsh-session-persistence-jsonl@0.1.5-rc.2+` 依赖 `node:zlib.createZstdCompress`（≥22.15）。预制包若仍带 22.14，启动前 `harness_runtime_heal` 会拒启或改用本机较新 Node；重建 CDN zip 时须内嵌 ≥22.15。`dshmarket` 因 undici 残缺暂入 boot denylist。

**互斥规则**：同一 `harness-runtime` 同时只保留一种口味的程序树；换装覆盖 `node` / `node_modules` / profile 声明，**默认保留** `.dsh` 会话与 Key。

**与「本机已装 DSH」**：并存、不共享 home。发现阶段最多借 Node/`bin.js`，**禁止**绑定 WorkBuddy/.dsh（现行 `align_harness_runtime_config`）。

## 3. 用户可见状态机（全生命周期）

### 3.1 装门四步（未就绪）

| 态 | 用户看到 | 下一跳 |
|----|----------|--------|
| 检测中 | 「正在确认本机环境…」 | → 选版本 / 填 Key / 已就绪 |
| 选版本 | 官方 / 预制 等权 + 体积说明 | → 安装中 |
| 安装中 | 阶段文案 + 0–100%；可取消 | → 填 Key / 失败可重试或换口味 |
| 填 Key | 一次粘贴；写本机 credentials | → 检测启动 |
| 检测启动 | 短状态后揭开内嵌 | → 就绪 |

**原则（ARCH-05 §4.2）**：复杂配置是摆设；日常只在编码智能体「环境维护」；系统设置能力接入**不设** Harness 页签。

### 3.2 运行期状态（已装）

| 层 | 取值 | 用户含义 |
|----|------|----------|
| 安装 | 未安装 / 待 Key / 已安装 | SetupGate vs 主区 |
| 服务 | 未启动 / 运行中(自管) / 运行中(外部占口) / 端口占用无响应 | 启停与「重启接管」 |
| 进度条 | 启停装载 READY / 失败需修 | SoftActivityBar + 结果态（禁安装条冒充启停） |
| 忙碌互斥 | 启/停/重启/修/恢复/卸 | 防连点 |

### 3.3 生命周期动作清单（六件套 + α）

| 动作 | 入口 | 行为要点 | 验收 |
|------|------|----------|------|
| 装 | SetupGate 双 CTA | CDN zip → 校验 → 解压 → 写路径；URL 空且有 Node 才 npm 回落 | 干净机可完成四步 |
| 启 | 主 CTA / 进页自动 | preflight → spawn → 等 HTTP + `?token=`；**外部占口须确认才接管**，禁止静默强杀 | 内嵌可聊 |
| 停 | 停止 | 停自管进程；外部需确认 | 口释放 |
| 重启 | 更多 | 强制自管 + 重注 Key | 清脏 env |
| 修 | **更多**（事故态临时露工具栏） | **自读 sidecar 日志**→清凭证僵锁、剔杀手插件、补 Web、sanitize；修完自动重启 | ≤2 步；**禁止**常驻主路径、禁止叫用户打开日志 |
| 回退 | 更多 → 恢复上次可用 | profile 配置快照（插件清单等） | 装坏插件可回 |
| 换装/升级 | 更多 → 升级运行时 | 换官方/预制程序树；默认可留会话与 Key；成功健康后**刷新还原点** | 跟上游版本 |
| 卸 | 更多 → 卸载 | 默认可留 `.dsh`；清安装树 | 再装可复用 Key/会话 |
| 日志/目录 | 更多 → 打开… | sidecar 日志、安装根、会话根 | **仅研发/客服** |
| 投喂/导出 | 投喂条 / 更多 | 办公链；会话 MD → output | 套件闭环 |

### 3.3.1 傻瓜日常 vs 事故底牌（主理人 · 2026-09-11）

**产品目标**：用户常态只会「装一次 → 启停/刷新/浏览器打开 → 干活」。修/还原是底牌，不是日常控件。

| 层级 | 用户感知 | 碰什么 | 何时用 | 不是什么 |
|------|----------|--------|--------|----------|
| **启 / 停** | 开关 | 进程 | 日常开用、下班关 | 不改文件、不换版本 |
| **刷新** | 重载页面 | 内嵌 Web | 页面卡住但服务仍活 | 不杀进程 |
| **重启** | 关掉再开 | 强杀端口 + 重注 Key + 再拉起 | Key 刚改、脏环境变量、进程假死但环境大体正常 | 不做深度自愈 |
| **修复（软修）** | 事故自检 | 读上次启动日志 → 清僵锁 / 剔杀手插件 / 理凭证 / 补 Web 联接 → **自动重启** | 起不来、插件拖死、凭证锁——**事故级** | **≠** 网吧一键还原；不擦会话、不换安装包 |
| **恢复上次可用（还原配置）** | 回到能开的配置点 | 只回滚 web profile 配置快照 | 用户乱装插件/改配置后搞挂 | **≠** 还原整个程序树；不删会话正文 |
| **升级/换装** | 换成新安装版 | 用当前官方/预制 zip 覆盖程序树 | 上游发版、运营推新 | 默认留 Key/会话 |
| **卸后重装 / 装门再装** | 接近「出厂程序面」 | 清安装树再下 zip | 修+还原都救不了 | 出厂面 = CDN 安装包，不是本机随便一个旧目录 |

**还原点（两套，勿混）**：

1. **出厂安装面** = CDN `harness-official-*.zip` / `harness-prefab-*.zip`（运营发版更新）。换装/重装才回到这一面。  
2. **上次可用配置点** = `profile_snapshots` 的 `last_good`（健康跑通、修复成功、**升级后再次健康**时刷新）。「恢复上次可用」只回这一面。

升级后**必须**在健康就绪时刷新 `last_good`（已有 `maybe_snapshot_after_healthy`；换装成功路径不得跳过）。旧版配置点不得覆盖新版程序语义时，以新健康快照为准。

**入口铁律**：

- 工具栏日常：**启停 · 浏览器打开 · 刷新 · 更多**。  
- 「修一下」默认在 **环境维护**；仅失败态临时出现在工具栏。  
- 禁止把修复做成第二主 CTA；禁止系统设置再配一套路径功课。

### 3.4 状态衔接矩阵（官方 / 预制 · 已装 / 未装 · 已启 / 未启 · 可升级）

> **主理人裁定（2026-09-14）**：初级版（官方精简）与预制版、新版升级、以及「安了/没安、启了/没启」的衔接必须靠谱；**不能影响用户正在用的应用**。本节供专家组论证后勾选 §8.10。

#### 3.4.1 正交四轴（禁止揉成一句话恐吓用户）

| 轴 | 取值 | 真相源 | 用户话术禁区 |
|----|------|--------|--------------|
| **口味** | `official` / `prefab` | `MANIFEST.flavor` | 勿称「强制」；预制文案用「预制必备版」 |
| **安装** | 未装 / 安装中 / 已装 / 换装中 | 安装树 + MANIFEST；装门 vs 主区 | 勿把「可更新」说成「未安装」 |
| **服务** | 未启 / 自管运行 / 外部占口 / 占用无响应 | sidecar + HTTP 探活 | 勿因可升级而隐藏「启动服务」 |
| **程序包钉扎** | 已对齐 / 可更新（可选） | `MANIFEST.version`±sha vs `harness.yml` `*_bundle_*` | 勿默认「必须立刻下几百 MB」 |

TOA Setup 发版 **≠** 强制换 Harness 程序树。切 `harness.yml` CDN 钉扎后，已装用户只见**弱提示**；未确认不得下载。

#### 3.4.2 主路径衔接（合法下一跳）

| 当前 | 允许动作 | 下一态 | 硬约束 |
|------|----------|--------|--------|
| 未装 | 选官方 / 选预制 → 装 | 安装中 → 待 Key → 未启已装 | 可取消；失败不留半残树话术须可重试 |
| 已装 · 未启 | **启动服务** | 运行中 | 有「可更新」条时仍可启动；**禁止**逼先更新 |
| 已装 · 运行中 | 停 / 刷新 / 浏览器打开 | 同安装态 | **禁止**静默换装、禁止进页 auto 下大包 |
| 已装 · 可更新 | 更新 / 不更新 / 今日不提醒 | 更新→换装中→已升级待启；或维持原安装继续用 | 确认后才下；默认保留 `.dsh`；成功后**禁 auto_start**，须用户点启动 |
| 换装中 | 取消 | 回到换装前安装树（若未覆盖完） | 取消不得抹 `.dsh` |
| 外部占口 | 刷新加载 / 用户确认后接管 | 自管运行 | **禁止**静默杀外部进程 |
| 事故（起不来） | 修一下 / 恢复上次可用 /（末路）换装 | 未启或运行中 | 无快照时**立刻人话失败**，禁止空转「正在恢复…」 |
| 卸载 | 确认；默认可留会话 | 未装 | 只清 TOA runtime |

#### 3.4.3 不影响用户应用（铁律 · 建议合入门禁）

1. **不抢业务**：升级/安装失败或取消，不得导致 TOA 其它模块不可用；Harness 页失败态留在本页。  
2. **不抢端口默认值**：发现外部 3082 已健康 → 优先「装入/刷新」；强杀须确认。  
3. **不静默大包**：进页、TOA 升级、检查更新路径均**禁止**自动下 Harness zip。  
4. **不抹会话与 Key**：换装/升级默认 `keep_user_data`；卸默认可选留 `.dsh`。  
5. **不洗用户插件**：预制升级时 `prefab_essential_plugins` 为空 = **只不扩包**，**禁止**把已装 bundles 洗成仅核心（2026-09-14 事故）；官方精简版才允许压到核心。升级路径必须：装前 `capture_profile_plugins` → 装后 `merge_profile_plugins` → `reinstall_missing_plugins`（registry 缺包自动 `dsh plugin add`；本地 link 失效只提示）。  
6. **不阻断启停**：程序包可更新只是条；主 CTA 仍是启动/停止。  
7. **不恐吓文案**：条目标「程序包可更新（可选）」+ 体积；禁止「不更新则无法使用」类措辞。  
8. **不空转恢复**：无 `last_good` 快照 → 状态栏一句说明如何备份；不进入长时间忙碌遮罩。  
9. **TOA 与 Harness 解耦发版**：Setup 可先发；Harness CDN 切钉扎另走 SOP-04 §5；已装用户可「今日不提醒」继续干活。

#### 3.4.4 点验清单（专家组 / 主理人）

| # | 场景 | 期望 |
|---|------|------|
| 1 | 干净机装官方 → 启 → 聊一句 | 四步无路径功课 |
| 2 | 干净机装预制 → 启 | 同上；flavor=prefab |
| 3 | 已装旧 MANIFEST，yml 钉新号 | 见可选更新条；点「今日不提醒」后**仍能启动**且会话在 |
| 4 | 运行中点更新 | 须确认；下载中可取消；成功后提示再点启动，不自动抢启 |
| 5 | 外部已占 3082 | 提示识别实例；不静默杀 |
| 6 | 无备份点「恢复上次可用」 | 立即人话失败，主区不假忙 |
| 7 | 更新失败/取消 | 原程序树仍可启（若未被破坏）；`.dsh` 仍在 |

自动化：在 `verify_harness_full_scenarios` / delivery 中覆盖「可更新不阻断启动」「无快照恢复快失败」（实现后勾选）。

## 4. 打包与运营（双版本制品）

### 4.1 谁带什么

| 制品 | 含 | 不含 |
|------|----|------|
| TOA Setup.exe | Host 代码、`vendor/dshm`、空路径 `harness.yml` | dsh zip、credentials、本机绝对路径 |
| CDN `harness-official-*.zip` | 便携 Node + dsh 核心树 + 空 `.dsh` 骨架 + MANIFEST | Key、会话、日志、WorkBuddy 路径 |
| CDN `harness-prefab-*.zip` | 同上 + 白名单插件已装进 profile | 同上；禁止 denylist 包 |

构建：`scripts/build_harness_prefab.py`（已知可用机）。  
发版 guard：禁止 zip / `.credentials.yaml` / 个人路径进主安装包（`release_config_guard`）。

### 4.2 运营更新节奏

1. 上游 dsh 发版 / TOA 钉扎版本变更  
2. 内测机装通 → 跑 Host 生命周期脚本  
3. 打 official + prefab 两包 → 算 sha256  
4. 上传 CDN → 改 `official_bundle_*` / `prefab_bundle_*`（及 shipped）  
5. 客户端：未装用户下新包；已装用户走「检查更新 / 换装」策略（见 §5）

配置键（`config/harness.yml`）：

- `official_bundle_url` / `sha256` / `version` / `size_hint_mb`
- `prefab_bundle_url` / `sha256` / `version` / `size_hint_mb`
- `prefab_essential_plugins: []`（主理人确认清单后方可非空）

### 4.3 当前缺口（论证前须知）

| 项 | 现状 | 整改门槛 |
|----|------|----------|
| CDN URL | **已填** `toa-service.yczh.tech/download/harness-*-0.1.5-rc.1.1.zip` | `verify_harness_cdn` HEAD 可达；sha256 与 shipped 对齐 |
| 必备插件白名单 | `[]`（主理人 2026-09-11：**先用现有能力**，不扩包） | 预制 zip ≈ 官方同核；日后加插件须 denylist 联审再建包 |
| 诊断包 | **已落地**「环境维护 → 导出诊断包」 | 脱敏 zip；不落 Key / credentials |
| 体积预期 | CDN zip ≈ **456 MB**；本机解压后约 **0.8 GB**（含 `.dsh` 会话会再涨） | 装门文案要说清「等一会儿」；禁静默大包 |

### 4.4 预制版全链路（升级 → 发布 → 用户下载）· 体验契约

> **术语**：代码 `flavor=prefab` = 用户文案「预制版」。  
> **现行策略**：预制白名单空 → 预制包内容与官方同核；用户「就用现在能用的」= **不必再扩插件**，只把升级/发布/下载链路跑顺。

#### 角色

| 角色 | 干什么 | 不干什么 |
|------|--------|----------|
| 研发/构包机 | 钉扎 dsh → 本机跑通 → `build_harness_prefab.py` 出 zip+sha256 | 不把 zip 打进 TOA Setup |
| 运营/CDN | 上传 `downloads/`、核对直链、改 nginx 如需 | 不改用户本机目录 |
| TOA 客户端 | 新用户四步下载；已装用户显式「更新环境」 | **禁止**进页静默下大包 |
| 用户 | 选版 / 贴 Key / 点更新 | 不读 sidecar 日志、不填路径 |

#### A. 升级预制版（研发侧 · 出新包）

```text
① 钉扎上游 dsh（例 0.1.5-rc.1）→ 开发机 TOA 内四步/启停修绿
② 确认白名单：现状 [] = 同核；若加插件 → denylist 复测通过才写 prefab_essential_plugins
③ 源目录：已知可用的 harness-runtime（含便携 node/ + node_modules）
④ python scripts/build_harness_prefab.py --source <runtime> --out packaging/dist/harness
⑤ 产出 harness-prefab-<ver>.zip + .sha256（及 official 对称包）
⑥ 沙箱自验：verify_harness_cdn / verify_harness_sandbox_clean（隔离端口，勿动用户 3082）
```

- 构包**剔除**：`.credentials*`、会话、日志、个人路径。  
- MANIFEST 写：`flavor/version/plugins/dsh_pinned`。  
- 失败标准：装不起、缺 Web 核心、含密钥 → **禁止上传**。

#### B. 发布预制版（运营侧 · 上 CDN + 改配置）

> **自动化（对标 SOP-04 Setup 两段式）**：细则见 `docs/规范/SOP-04-打包发版.md` §5。

```text
① 上传（Agent）：
     powershell -File cloud/deploy/upload_harness.ps1 -BundleVersion <ver>
   → official + prefab 两 zip（及 .sha256 / meta）进 /opt/yczh-portal/downloads/
② HEAD 直链（脚本内已做）≈ size_hint
③ 【人工闸门】主理人确认「切配置」——未确认禁止改 yml
④ 切配置（Agent）：
     python scripts/sync_harness_bundles.py --from-dist --version <ver> --apply --verify-cdn
   双写：config/harness.yml + packaging/shipped_config/harness.yml
   字段：official_* / prefab_*（url / sha256 / version / size_hint_mb）
⑤ python scripts/verify_harness_cdn.py （交付门禁必过；④ 已会再跑一遍）
⑥ 是否发 TOA 新 Setup：
     - 仅换 CDN 钉扎 → 可 Hotfix 配置（已装用户靠「更新环境」吃新包）
     - Host 代码也变 → 走正常 TOA 发版（SOP-04 §2）
```

- **旧 zip 保留一段时间**（回滚）；新用户永远指向 yml 里最新 URL。  
- Setup.exe **永不**内嵌几百 MB zip（`release_config_guard`）。
#### C. 用户下载预制版（客户端体验）

**C1 从未装过（干净机）**

| 步 | 用户看见 | 系统行为 |
|----|----------|----------|
| 1 | 引擎 → 编码智能体 →「安装预制版」 | 拉 CDN zip；分阶段进度（连接/下载/校验/解压）；可取消 |
| 2 | 等待（体积大，须人话「大约几百 MB」） | sha256 校验失败 → 人话重试，不甩路径 |
| 3 | 粘贴一次对话密钥 | 写本机 credentials；不上传 TOA 云 |
| 4 | 自动检测启动 → 内嵌可用 | 默认 embed；外开自点 |

失败：CDN 挂 / 缺 Node 回落 → 人话；引导「环境维护 → 修一下」，**不**叫去系统设置填路径。

**C2 已装过（你这种 · 本机已有 runtime）**

| 步 | 用户看见 | 系统行为 |
|----|----------|----------|
| 日常 | 启停 / 刷新 / 浏览器打开 | 不动安装树 |
| 换新包 | **页顶提示**：更新 / 不更新 / 今日不提醒 | 确认后才下 zip；覆盖程序树，会话与 Key 默认保留 → 切装门进度 → **页示「已升级完成」→ 点启动服务**（禁 auto_start 抢跑） |
| 搞挂 | 「修一下」/「回到上次能用的样子」 | 软修 ≠ 重新下包；还原 ≠ 出厂 zip |
| 不要了 | 卸载（默认可留会话） | 只清 TOA runtime；不扫盘 |

- **不**进页静默下载大包；弱提示对比 `MANIFEST.version` 与 yml 钉扎。  
- 「不更新」= 本会话免打扰；「今日不提醒」= 落盘到当日（同目标版本）。  
- 更新中可见进度（已下/总量 MB、粗略剩余时间）；取消安全；失败回到原可工作区。  
- 基础版侧栏含 `harness_agent`（`config/editions/standalone.yml`）。
**C3 体积与文案（体验硬约束）**

- 装门/更新确认须暗示等待与体积（`size_hint_mb`）。  
- 进度条真实阶段，禁止假 100%。  
- 成功：内嵌可聊即收工；`show_saved`/状态栏短句即可。

#### D. 全链路验收清单（Agent 可沙箱；主理人可选点）

| # | 项 | 自动化 |
|---|-----|--------|
| 1 | CDN HEAD + sha 配置对齐 | `verify_harness_cdn` |
| 2 | 沙箱装树启停（隔离 13082） | `verify_harness_sandbox_clean` |
| 3 | 契约：更新环境切装门 + 强制 last_good | `verify_harness_full_scenarios` |
| 4 | 交付总门 | `verify_harness_delivery.py`（默认不碰用户 3082） |
| 5 | 构包机人工：打 zip → 上传 → 改 yml → 再跑 1 | 运营 |
