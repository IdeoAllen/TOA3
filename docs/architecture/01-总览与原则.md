# 01 · 总览与原则

## 1. 产品定位

**TOA3**（Training Operations Assistant 3.0）是「赋能培训运营助手 / 运营宝」的 **桌面端主开发线**，面向培训运营场景：材料生成、目录检查、桌卡、日程、简历等业务工具的统一外壳。

| 项目 | 路径 | 技术栈 | 状态 |
|------|------|--------|------|
| TOA2 | `../TOA` | tkinter + ttkbootstrap | **封板留存**，仅维护 |
| TOA3 | 本仓库 | PySide6 + Qt Designer + QSS | **主开发线** |

## 2. 为什么要重构

TOA2 在 Windows 上通过 ttk 做全局主题时，存在：

- 控件高度、可点区域难以统一
- 表格选中、勾选、进度条易回退系统默认色
- 样式逻辑分散（`theme_manager`、`ttk_solid_layouts`、enforcer 多层兜底）
- **无可视化拖拽**，新功能 UI 成本高

TOA3 选用 **Qt**：全局 QSS、原生控件一致性好，**Qt Designer** 支持拖拽布局，长期扩展更可控。

## 3. 架构目标

1. **美观正规**：商务风（DMS 五色），字号/间距/窗口统一规格（`ui_spec.yml`）
2. **简捷实用**：单模块主任务 + 示例数据 + 状态栏反馈
3. **架构清晰**：布局（`.ui`）与逻辑（`.py`）分离，分层可扩展
4. **全局统一**：一处换主题，全应用生效
5. **安全可靠**：统一异常、三方 integrations 层、license 门禁
6. **可维护**：业务只引用 `widgets/` 控件库，禁止散落样式

## 4. 核心设计原则

### 4.1 分层依赖（只允许向下）

```
业务 modules/*
    ↓ 只用
widgets/* + ui/*.ui
    ↓ 只用
app/theme_loader + resources/qss
    ↓ 只读
config/themes/*.json
```

禁止：业务页 `setStyleSheet`、硬编码 `#2563EB`、裸 `QPushButton` 当主按钮。

### 4.2 控件库即标准

`modules/gallery`（控件库页）展示 **全部** 允许使用的控件与状态。业务页选用的控件必须是控件库的子集（登记在 `widgets/`）。

### 4.3 主题单一数据源

- **色板**：`config/themes/<id>.json` 的 `palette`（与 DMS / TOA2 同源）
- **皮肤**：`scripts/gen_qss_from_theme.py` 生成 `resources/qss/<id>.qss`
- **运行时**：`app/theme_loader.apply_theme(app, theme_id)`

不维护「Designer 里一套色 + 代码里一套色」。

### 4.4 TOA2 业务逻辑可迁、UI 不迁

- 算法、文件处理、模板生成等 **Python 逻辑** 可从 TOA2 `modules/` 复制/改写
- tkinter UI **不移植**；在 TOA3 用 `.ui` + `widgets` 重做界面

## 5. 技术选型

| 领域 | 选型 | 说明 |
|------|------|------|
| UI 框架 | PySide6 6.6+ | 官方 Qt6 Python 绑定 |
| 布局工具 | Qt Designer | `pyside6-designer`，`.ui` 存 `ui/` |
| 主题 | 自研 JSON→QSS | DMS 商务色，非绑死 Material |
| 参考 | qt-material | 仅参考 QSS 组织方式，色板用自己的 JSON |
| 配置 | YAML + JSON | 与 TOA2 `config/` 概念对齐，逐步共用 |
| 打包 | PyInstaller（规划） | 独立 `packaging/`，待阶段 9 落地 |
