# 12 · 办公套件壳层与系统介入

> 主理人裁定：办公室人员安装 TOA3 = 集成剪贴板、截图、目录、文件、桌面、业务等常用办公效率工具。  
> Agent 规则：`.cursor/rules/toa3-office-suite-shell.mdc`  
> 文案同源：`config/product.yml` → `vision`

---

## 1. 产品定位

### 1.1 一句话

**装一个 TOA3，等于装齐日常办公效率工具箱**——不是功能堆砌，而是对标头部、一站集成、键位跟手。

### 1.2 能力地图

| 用户心智 | 独立软件类比 | TOA3 落点 | 介入方式 |
|----------|--------------|-----------|----------|
| 剪贴板增强 | ClipX / Ditto | `clipboard_history` | 全局热键 popup + 后台捕获 |
| 截图标注 | 微信 / Snipaste | `screenshot_tool` + overlay | 全局热键全屏覆盖 |
| 快速记事 | 系统便笺 | `quick_notepad` | 热键唤起主窗 |
| 文件桌面 | Finder / 资源管理器增强 | `column_preview` | 壳内模块 + 预览 |
| 目录/交付 | 自建脚本 / 手工 | `directory_*` | 壳内向导 |
| 文件批处理 | 小工具合集 | `batch_rename` 等 | 壳内模块 |
| 培训业务 | 表格/模板/日程 | `business` 组 | 壳内模块 |

### 1.3 集成标准

引用 `product.yml` `vision.promises`：

- 高频刚需做强；每项对标品类 Top3（见 Top3 门禁）。
- 同类能力不输独立 App **主路径**。
- 本地优先、可离线；输出路径经 `storage_paths`。

## 2. 壳层信息架构（目标态）

### 2.0 术语（主理人裁定）

| 层级 | 用户称谓 | 技术键 | 位置 |
|------|----------|--------|------|
| 一级 | **子模块**（亦称 **子系统**） | `group_id` | 顶栏 Tab |
| 二级 | **功能模块** | `menu_items[].id` | 侧栏 |
| 三级 | **任务页** | `BasePage` | 主内容区 |

每个顶栏 Tab 是一个 **子模块**；在架构上同时是一个 **子系统**（办公、图片、业务等）。代码仍用 `GROUP_ORDER` / `select_domain`。

### 2.1 布局示意

```
┌─ ShellHeader ─────────────────────────────────────────────┐
│ Logo  品牌名                    用户 主题 设置 关于 …      │
├─ ShellSubHeader（一级 · 子模块 / 子系统 Tab）──────────────┤
│ [首页] [办公] [图片] [目录] [文件] [业务] [系统]            │
├─ ShellSubHeader（可选 · 子模块内快捷动作）─────────────────┤
│ 如：办公子系统 → 截图 | 剪贴板 | 记事   （高频 one-click）  │
├──────────┬────────────────────────────────────────────────┤
│ 侧栏     │ ModuleHost（BasePage）                          │
│ （二级   │                                                 │
│ 功能模块）│                                                 │
│ 当前子   │                                                 │
│ 系统列表 │                                                 │
├──────────┴────────────────────────────────────────────────┤
│ StatusBar                                                 │
└───────────────────────────────────────────────────────────┘
```

### 2.2 一级 · 顶栏子模块（子系统）

- **数据源**：`menu_registry.GROUP_ORDER` + `GROUP_LABELS`，与 `config/product.yml` `module_groups` 一致。
- **交互**：单击子模块 Tab → 侧栏刷新为该子系统下的功能模块；再次单击已选 Tab 可滚动侧栏到顶（P2）。
- **现状**：`ShellSubHeader` 已承载子模块 Tab；侧栏按当前子系统过滤。

### 2.3 二级 · 侧栏（功能模块）

- **只显示当前子模块**下的可见功能模块（`show: true` + manifest + license）。
- 子模块内可按 `order` 排序；可选保留小组标题——须来自配置，禁止硬编码。
- 折叠侧栏 / 4px 展开轨行为保持不变（沉浸全屏兼容）。

### 2.4 三级 · 模块页

- `BasePage` + 懒加载；`on_enter` / `on_leave` / `report_status`。
- 业务页**不得**重复实现子模块导航或全局功能模块列表。

### 2.5 配置约定（未来）

```yaml
# config/app.yml 建议扩展（P2）
shell:
  domain_bar: true          # 顶栏子模块 Tab（实现名 domain_bar）
  domain_shortcuts:         # 子模块内顶栏快捷钮（可选）
    office: [screenshot_tool, clipboard_history, quick_notepad]
```

实现前须在架构评审中勾选；Agent 不得未经主理人确认擅自改 `app.yml` 壳结构字段。

## 3. 系统介入层

「炸场但无感」= **用户不打开放置 TOA 也能完成高频动作**，且 **Esc/完成即回到原工作**，不长期占焦点。

### 3.1 五层模型

| 层 | 说明 | 示例 |
|----|------|------|
| **Ambient** | 零 UI 后台 | 剪贴板 watcher、schedule 提醒 |
| **Summon** | 唤起主窗或模块 | Alt+N 记事、托盘菜单、`_summon_module` |
| **Overlay** | 临时全屏/浮层 | 截图标注层、剪贴板快贴 |
| **Chain** | 产出物衔接下一能力 | 截图 → OCR 页；标注完成 → 复制/保存 |
| **Palette** | 命令面板 | Ctrl+K 搜模块（roadmap） |

### 3.2 现有代码锚点

| 能力 | 文件 |
|------|------|
| 壳入口 | `app/shell.py` — `navigate`, `_summon_module`, `_open_clipboard_quick`, `jump_menu_group` |
| 热键 | `services/hotkey_service.py` + `config/app.yml` `hotkeys` |
| 托盘 | `services/tray_service.py` |
| 截图覆盖 | `services/screenshot_overlay.py` |
| 剪贴板 popup | `modules/clipboard_history/clipboard_popup.py` |
| 剪贴板监听 | `modules/clipboard_history/clipboard_watcher.py` |

### 3.3 介入铁律

1. **可关闭**：每项全局介入须在设置或 `hotkeys` 可设为 `none`。
2. **可退出**：Overlay 必须 Esc / 完成按钮明确退出；不得无头全屏。
3. **不卡 UI**：热键路径禁止同步 30s 级网络（DMS health 教训）。
4. **双轨发现**：Wave★ 功能模块必须同时满足「壳内子模块→侧栏可找到」与「热键或托盘或 Overlay 至少一种」。
5. **菜单单一真相源**：介入入口最终 `navigate(module_id)`，`module_id` 必须在 `menu_items` 登记。

### 3.4 子模块内高频快捷条（建议）

办公子系统顶栏可固定 3 钮（与 Wave★ 一致）：

- 截图 · `Alt+A` / `Alt+Shift+A`
- 剪贴板 · `Alt+Shift+C`
- 记事 · `Alt+N`

其它域按主理人确认扩展；**不得**占满顶栏。
