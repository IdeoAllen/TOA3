## 1. 用户场景（必填）

| 项 | 内容 |
|----|------|
| 谁 | 行政白领、培训运营（交材料、合同扫描、课件汇编） |
| 何时 | 多份扫描/导出 PDF 需合成一份发出；或从大 PDF 拆出单章/抽页 |
| 输入 | 一个或多个本地 PDF；合并顺序；拆分规则（每 N 页 / 按页码范围）；抽页页码列表 |
| 输出 | 新 PDF 落 `module_output_dir("pdf_toolkit")`；完成 `show_saved` |
| 失败体验 | 加密/损坏 PDF 明确警告；部分失败列出文件名；不静默丢页 |

**范围锁死（否决堆功能）**：仅 **合并 / 拆分 / 按页提取**。不做转 Word、OCR、水印、压缩、书签编辑、页面旋转（除非合并时必须保留旋转元数据）。

## 3. 取长补短矩阵

| 维度 | PDFsam | ABC/格式大师 | PDF24 | **TOA 采纳** |
|------|--------|--------------|-------|--------------|
| 核心流程 | 任务式：选文件→排序→出文件 | 专区多页签 | 单任务极简 | **单页三模式，一次一事** |
| 交互细节 | 拖拽排序、预览页数 | 规则多 | 少选项 | **拖拽调序 + 页数合计** |
| 性能 | 大文件流式 | 批量 | 中小文件快 | **工作线程；进页零联网** |
| 能力深度 | 合并/拆/混排/旋转 | 转档+水印堆满 | 工具多 | **只做三件套做强** |
| 明显短板 | 独立安装、与办公套件割裂 | 功能噪音 | 品牌外跳 | 避开百工具；与文档合成边界清晰 |

### 必学（至少 3 条）

1. 合并前可调序，页数可见  
2. 拆分规则一眼懂（每 N 页 / 范围）  
3. 本地处理、结果路径可打开  

### 明确不学 / 否决

1. PDF↔Office 互转、OCR、加水印  
2. 云端上传处理  
3. 复杂书签/目录树编辑器

| 1 | **合并顺序可拖且页数合计防发错** | 发材料前一眼看出「几份、多少页、谁先谁后」 | 调序后列表即时更新；合并输出总页数=各输入页数之和 | 已确认 |

## 4. 技术方案（过门才写码）

| 项 | 结论 |
|----|------|
| 选定栈 / 库 | 优先 **pypdf**；加密/损坏边界测不过再评估 pikepdf |
| 否决项及原因 | 不上商业 SDK；不做 Ghostscript；禁止 UI 线程读写大 PDF |
| 架构落点 | `modules/pdf_toolkit/` + `pdf_service.py`；菜单 `app.yml` show 待 mvp；`storage.yml` 已登记 |
| 性能约束 | 工作线程；进页零联网；大文件进度走状态栏 |
| 品质验收 | 合并页数正确；拆分/抽页可开；加密样本点名失败；文案指向文档合成边界 |
| 如何兑现 §3.5 | ① 拖拽+页数合计 ② 逐项失败可续 ③ 仅 PDF 入口+边界文案；完成仍走 `show_saved` |
