## 0. 复杂度与工作量研判（本轮交付）

| 问题 | 结论 |
|------|------|
| 复杂吗？ | **中高**：IMAP 同步 + 本地库 + HTML 渲染 + 凭证，比剪贴板/记事本难一档；比 Harness 整机托管简单 |
| 工作量？ | **稳定 MVP（单账号 IMAP+SMTP+附件）约 4–7 人周**；赶工「能打开能发」约 2.5–4 人周（不推荐当 done） |
| 能赶上企微？ | **不能、也不该追**。企微=云端多账号通讯套件；TOA=本机可信邮箱工作台，只保住绑定/收发/附件稳定 |

### 仓库现状（不可「扩一点通知邮件」交差）

| 已有 | 缺口 |
|------|------|
| `services/notify_channels.py` 出站 SMTP 纯文本通知 | 无 IMAP、无附件、无 HTML、无客户端 UI |
| `config/integrations.yml` → `email`（通知通道） | 与「用户邮箱客户端」应 **分轨**；密码未走 secrets |
| QWebEngine / 记事本 `setHtml` 先例；三栏可对标 `clipboard_history` | 协议层与增量同步 **绿地** |

### 与企微边界（硬）

| 能力 | 企微 | TOA MVP |
|------|------|---------|
| 绑定 / 收发 / 附件 | ✅ | ✅ 必做 |
| 多账号统一收件箱、话题、转发到聊天 | ✅ | ❌ 不做 |
| Exchange / M365 OAuth、企业通讯录 | ✅ | ❌ MVP 不做（+2～4 人周且另开） |
| 海量云端秒搜 | ✅ | 本机 SQLite 即可 |
| 稳定性卖点 | 云端团队 | 本地协议容错 + 后台线程 + 断点续同步 |

### 工作量拆解（1 名熟悉 TOA 的开发）

| 阶段 | 人周 |
|------|------|
| Top3 共创过门 + 菜单/manifest | 0.5 |
| IMAP 同步 + SMTP 发信（含附件）+ 线程 | 1.5–2.5 |
| SQLite + 附件落盘 + secrets | 0.5–1 |
| 绑定向导 + 三栏 + 写信 | 1–1.5 |
| QQ/163/Outlook 实机稳定化 | 1–1.5 |
| **合计稳定 MVP** | **约 4–7** |

稳定性风险在 **IMAP 边角与授权码 UX**，不在画三栏 UI。

- Wave★ 点验与邮箱等板块允许 **分头并行**（STD-01 A0.8 · B9）；统筹收口发版。  
- 专家组已 `approved` → **独立开轨**写码（约 4–7 人周稳定 MVP；默认 `show:false`）。  
- 主理人只做点验 / 升显 / 设当前版，**不审** §3.5。

## 1. 用户场景（必填）

| 项 | 内容 |
|----|------|
| 谁 | 办公室人员（已装 TOA 办公套件；日常用 QQ/163/Outlook 个人或企业邮箱） |
| 何时 | 要在本机收通知邮件、回一封带附件的业务信，不想为「看一眼邮箱」再开一套重客户端或切网页 |
| 输入 | 邮箱账号 + 授权码/应用密码；收件时点收取/后台定时；发信：收件人、主题、正文、附件 |
| 输出 | 本机列表可见未读；详情可读（含 HTML）；发出去的信在「已发送」；附件可下载到模块输出目录 |
| 失败体验 | 错密码 / 未开 IMAP / 需授权码 → **人话诊断**（指向 QQ/163 设置页路径），不卡死壳；断网恢复后能续同 |

**边界（硬 · MVP）**

| 做 | 不做 |
|----|------|
| 单账号 IMAP+SMTP；预设 QQ/163/Outlook.com/Gmail；手填高级 | 企微式话题、转发到聊天、标签体系 |
| 收件箱/已发送/已删除；未读；附件收发 | 多账号统一收件箱（二期 +1～2 人周） |
| 页内私有 WebEngine 预览 HTML | Exchange EWS / Graph OAuth（另开） |
| 凭证 secrets；网络全在工作线程 | POP3；日历；规则引擎；服务端搜索 |

## 3. 取长补短（服务亮点，不是抄功能表）

| 维度 | 企微邮件 | Foxmail/大师 | 网页邮箱 | **我们可偷师 / 必须避开** |
|------|----------|--------------|----------|---------------------------|
| 核心流程 | 套件内一站 | 独立重客户端 | 浏览器登录 | 偷：进 TOA 就能办；避：造第二套企微 |
| 交互 | 三栏成熟 | 功能堆叠 | 零安装 | 偷：三栏够用；避：话题/标签/拒收全家桶 |
| 性能 | 云端索引 | 本机同步 | 随网 | **钉：断线续同、UI 不堵** |
| 俗套 | 「企业统一通讯」 | 「全能邮箱」 | — | 不自称赶上企微 |

### 可偷师（至少 3 条）

1. 绑定页：**预设厂商模板** + 授权码说明（Foxmail 级）  
2. 列表/详情三栏够用即可（企微布局可参考，不抄功能表）  
3. 失败可诊断、可重试（Thunderbird/大师都强调「连不上时说人话」）  

### 明确不学 / 否决

1. 转发到聊天、话题、企业通讯录 SSO  
2. 以「对标企微全功能」为验收  
3. 与 `integrations.email` 通知通道混成同一套配置（通知仍独立）

## 3.2 设计亮点挖掘（产品角度 · 必填）

| 候选亮点（一句话） | 为何不落俗套 | 可感知？ | 可测？ | 入选 §3.5？ |
|--------------------|--------------|----------|--------|-------------|
| **套件内本机邮箱工作台**：热键/侧栏进页即收发，凭证与索引不进第三方云邮箱 App | 不是又装一个 Foxmail；卖的是「办公套件里办完邮件这件事」 | 是 | 是 | **是 → #1** |
| **绑定以授权码诊断为第一公民**：预设 QQ/163 等；失败给出「开 IMAP / 应用密码」步骤，而非 IMAP 术语墙 | 竞品常假定用户懂协议；国内真实翻车点在授权码 | 是 | 是 | **是 → #2** |
| **稳定同步契约可见**：增量 UID、断网恢复续同、大附件不卡 UI；状态栏可说清「同步中/失败原因」 | 不卖「功能多」，卖「敢日常挂着」 | 是 | 是 | **是 → #3** |
| 三栏 UI 像企微 | 视觉抄袭非独到 | 中 | 弱 | **否** |
| 多账号统一收件箱 | 企微主战场；工期暴涨 | — | — | **否**（明确不做） |
| AI 写邮件 / 智能摘要 | 俗套且偏航核心稳定 | — | — | **否** |
| 本地优先 / 统一体验 / show_saved | 平台通例 | 弱 | — | **否**（不作独到） |

### 俗套否决清单

| 俗套说法 | 本功能为何不用它当独到 |
|----------|------------------------|
| 「一键完成 / 智能 / AI」 | 邮件核心是协议可靠，不是生成文案 |
| 「统一体验 / 界面好看」 | 平台通例 |
| 「本地优先」 | 桌面客户端通例；须落到同步契约才算数 |
| 「赶上企微」 | 产品谎言；边界上已否决 |
| show_saved / 打开目录 | 平台铁律，不作卖点 |

## 4. 技术方案（过门才写码 · 草案）

| 项 | 结论 |
|----|------|
| 选定栈 / 库 | Python 标准库 `imaplib` + `smtplib` + `email`；本地 SQLite；页内私有 `QWebEngineView` 渲染 HTML |
| 否决项及原因 | 复用通知 `integrations.email` 当账户库（职责混乱）；占用 `shared_local_webengine`（与引擎页冲突）；MVP 上 OAuth/Exchange |
| 架构落点 | `modules/email_client/`（page + service + mail_store）；`services/mail/` 协议层；凭证 secrets；**禁止**业务页直连 IMAP |
| 性能约束 | 进页/热键禁同步长联网；同步与收发在工作线程；附件大小上限 + 进度 |
| 品质验收 | QQ + 163 + 至少一家国际 IMAP 实机；断网续同；错密诊断；`show_saved` 仅用于附件/导出落盘 |
| 如何兑现 §3.5 | #1 菜单可发现 + 完整主路径；#2 绑定向导文案与诊断码；#3 `mail_store` UID + 线程模型 + SoftActivity/状态提示 |
