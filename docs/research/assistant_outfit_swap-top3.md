## 1. 用户场景（必填）

| 项 | 内容 |
|----|------|
| 谁 | 教务/培训运营（开班前或课中整理助教打卡材料） |
| 何时 | 助教已拍打卡照，但着装不合「商务装」要求，需统一成可交付口径 |
| 输入 | 本机目录（典型：班级下「助教打卡」照片夹）；选定服装风格（西服 / 白衬衫 / 休闲装 / 其它分格预设） |
| 输出 | 目录内图片**全量**复刻新装；**仅改服装**；水印/时间戳/角标/其它叠字与背景信息保持不变；落盘旁路目录（默认不覆写原图） |
| 失败体验 | 无图 → 人话提示；引擎未就绪 → 引导启用本机 Comfy/图像能力，**不**在进页同步长联网；单张失败可跳过并汇总，不堵整批 |

**产品句**：不是「美图式单张试衣」，而是「培训交付用的助教打卡照目录，一键统一着装」。

**边界（硬）**

| 做 | 不做 |
|----|------|
| 目录级批量换装 + 着装预设包 | 电商虚拟试衣 / 海量 SKU 试穿 |
| 保脸、保姿态（打卡身份可信） | 换脸、换人、美颜整容向 |
| 本机目录 → 本机产物（integrations 出图） | 进页强制联网探测；Portal 远程批处理 |
| 可串班级交付链 | 替代 Comfy 原版节点编辑（那是引擎页） |

## 3. 取长补短（服务亮点，不是抄功能表）

| 维度 | 美图单张换装 | Try-On API | 文件夹+即梦 | **我们可偷师 / 必须避开** |
|------|--------------|------------|-------------|---------------------------|
| 核心流程 | 上传→选衣→出一张 | 人+衣图→试穿 | 逐张改提示词 | 偷：选风格即出；避：单张自助心智 |
| 交互 | 轻、好看 | 开发者向 | 零产品 | 偷：目录选一次；避：要用户懂提示词 |
| 能力深度 | 证件规格强 | 衣物还原强 | 不稳定 | **钉：打卡身份 + 商务着装口径** |
| 俗套 | 「AI 一键换装」 | 「虚拟试衣间」 | 无 | 不自称通用 AI 试衣 |

### 可偷师（至少 3 条）

1. 风格用**可见预设**（西服/白衬衫…），不要空白提示词框当主路径  
2. 批量要有进度与失败清单，不能「黑盒跑完才发现翻车」  
3. 默认**旁路输出目录**，原图可回退（打卡材料怕误删）  

### 明确不学 / 否决

1. 电商试穿（衣架图+模特图双输入主路径）  
2. 换脸 / 换背景当主卖点（交付链另有工具）  
3. 进页同步探测云端、强制登录另一套账号

## 3.2 设计亮点挖掘（产品角度 · 必填）

| 候选亮点（一句话） | 为何不落俗套 | 可感知？ | 可测？ | 入选 §3.5？ |
|--------------------|--------------|----------|--------|-------------|
| **打卡目录全量一键**：选文件夹即枚举全量换装 | 竞品要么单张证件照，要么电商试穿；我们钉「班级助教打卡目录」 | 是 | 是 | **是 → #1** |
| **培训着装预设包**：西服/白衬衫/休闲等对齐商务着装口径 | 不是海量时尚 SKU；与招聘稿「需着商务装」同一话术体系 | 是 | 是 | **是 → #2** |
| **身份优先交付**：保脸保姿态；旁路输出同构目录可串水印/交付 | 打卡照要「还是本人」；产物进培训材料链，不是美图相册 | 是 | 是 | **是 → #3** |
| 「AI 智能一键换装」口号 | 品类滥调 | 弱 | — | **否** |
| 虚拟试衣间 / 衣架图双上传 | 电商心智，偏离打卡 | — | — | **否** |
| 统一体验 / 高颜值画廊 | 平台通例 | 弱 | — | **否** |
| show_saved / 打开目录 | 平台铁律 | 是 | 是 | **否**（不作独到） |
| 进页调起完整 Comfy 节点图 | 那是引擎页职责 | — | — | **否**（可作后端，不作卖点） |

### 俗套否决清单

| 俗套说法 | 本功能为何不用它当独到 |
|----------|------------------------|
| 「一键 / 智能 / AI 换装」 | 全品类都在喊；我们要钉场景 |
| 「本地优先」 | 全产品通例 |
| 「show_saved / 打开目录」 | 平台铁律 |
| 「海量服装模板 / 虚拟试衣」 | 电商词；我们只要培训商务着装包 |
| 「媒体工坊也能出图」 | 通用创作台≠打卡目录批处理 |

## 3.5 三个独到之处（与主理人共创 · 门禁核心）

| # | 独到主张（一句话） | 用户可感知价值 | 可测验收 | 论证结论 |
|---|--------------------|----------------|----------|----------|
| 1 | **打卡目录全量一键**：选定助教打卡照片目录后，对目录内图片全量换装，不必逐张打开美图/即梦 | 开班前一夹照片一次搞定 | 选含 N 张图的目录 → 产出 N 张（失败项进清单）；无图给人话 | 已确认 |
| 2 | **培训着装预设包**：主路径点选西服 / 白衬衫 / 休闲装等业务预设（可扩展分格），对齐「需着商务装」口径，不靠空白提示词 | 运营不懂 SD 也能选对照装 | 切换预设后批量结果服装语义可区分；主路径无强制手写 prompt | 已确认 |
| 3 | **只换服装 · 旁路交付**：保脸保姿态；**水印及其它叠字/信息不变**；默认旁路输出（保留原图）；单张失败不中断整批 | 打卡仍是本人且材料信息完整；翻车可回退 | 原目录原图仍在；提示词/验收强调水印保留；失败清单可复跑 | 已确认 |

共创纪要：

- 输出默认：`原目录/_换装_<风格>/`（旁路，不覆写）。  
- 出图：经 `integrations.image_gen` 的参考图编辑（优先支持 edit 的云端档，如豆包 Seedream）；进页不阻塞联网探测。  
- 硬约束（主理人 2026-09-08）：**只给人换服装，水印等其它信息都保持不变。**  
- 首批预设：西服、白衬衫、商务休闲、女装商务正装。

## 4. 技术方案（过门才写码）

| 项 | 结论 |
|----|------|
| 选定栈 / 库 | 页面 `modules/assistant_outfit_swap/`；重活 QThread；出图走 `services/integrations`（Comfy / image_gen），禁止业务直连第三方 SDK |
| 否决项及原因 | 否决把 Comfy 原版节点当业务主 UI；否决进页同步长联网；否决默认覆写原图 |
| 架构落点 | 业务侧栏；可选读取 `class_session_handoff` 预填根路径；下游可跳转 `watermark_photo_generator` |
| 性能约束 | 进页/热键禁同步长联网；批处理有进度条；低配可排队逐张 |
| 品质验收 | 见 §3.5；**抽查水印仍在**；完成必须 `show_saved`；gaps 点验后写回 manifest |
| 如何兑现 §3.5 | #1 目录枚举+线程批处理；#2 预设→锁定 edit prompt；#3 旁路 `_换装_*` + prompt 硬约束保水印 + 失败清单 |
