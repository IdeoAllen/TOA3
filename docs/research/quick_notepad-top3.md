## 1. 用户场景（必填）

| 项 | 内容 |
|----|------|
| 谁 | 办公室人员：会中速记、电话旁草稿、粘贴前整理；偶尔要标题/加粗/列表/插图，偶发导入 `.md` |
| 何时 | 热键或壳内打开记事；多数时间在「打字」而非「管模式」 |
| 输入 | 键盘；剪贴板文本/图；本地图片；导入 Markdown |
| 输出 | 本地笔记（大纲可找）；复制回剪贴板（最好保留格式）；导出/带走不强迫上云 |
| 失败体验 | 未保存丢字、格式乱、找不到刚写的、模式切换把正文弄丢、说明文字比正文还抢眼 |

产品承诺对照（清单）：热键秒开 · 列表搜索 · 与剪贴板一键互拷 · 本地不丢；集成承诺：同类能力不输独立 App 主路径。

## 2. Top3 对标产品

场景锁定：**桌面优先 · 快速记事 · Markdown 可进可出 · 所见即所得排版 · 本地插图**。  
故入选「写作面」头部，而非 Windows Sticky Notes / 纯记事本（那是 v1 轻量基线）。

| # | 产品 | 平台 | 为何入选 | 资料链接 |
|---|------|------|----------|----------|
| 1 | **Typora** | Win/macOS/Linux | 真·单面 WYSIWYG Markdown 标杆：打完即见排版，无「编辑/预览」脑分裂 | [typora.io](https://typora.io) |
| 2 | **Obsidian**（Live Preview） | 桌面优先 | 本地 `.md` + 插图稳；Live Preview 接近所见即所得且保留源码可探 | [obsidian.md](https://obsidian.md) |
| 3 | **Notion Desktop** | Win/macOS | 办公向块级所见即所得；斜杠/选区工具条；「像文档」而非「像表单」 | [notion.so](https://www.notion.so) |

（可选参考，不计入 Top3 门禁）：Bear（美学与标签）、OneNote（办公速记+图，但 MD 弱）、Craft（版式精致，偏生态封闭）。

## 3. 取长补短矩阵

| 维度 | Typora | Obsidian Live Preview | Notion Desktop | **TOA 采纳** |
|------|--------|------------------------|----------------|--------------|
| 核心流程 | 打开即写；语法写完即渲染；导出多样 | 库内点笔记即写；源码/预览可切换但不逼默认分屏 | 空白页直接打字；`/` 出块；自动保存感强 | **打开即写当前条**；默认一块写作面；自动落盘感；导入 MD→可排版 |
| 交互细节 | 几乎无模式开关；选区/行内工具克制；沉浸 | 光标行露语法，其余已渲染；命令面板 | 悬浮/气泡格式条；块柄；预览≠第二编辑模式 | **砍掉叠床架屋的「编辑\|预览」**；工具栏图标化+选区态；少说明长句 |
| 性能 / 延迟 | 单文档轻；大表/大图偶卡 | 插件多时重；纯写尚可 | 云同步偶顿 | 热键/进页不联网；大图限宽已有；禁同步探测 |
| 能力深度 | 表/公式/导出深；非知识库 | 双链/图谱/插件极深 | 库表/协作极深 | **只做办公速记+轻排版+图+互拷**；不碰双链/库表 |
| 明显短板（我们避开） | 单文件取向、无套件链 | 偏知识管理、上手概念多 | 云优先、导出/MD 弱、体量大 | 不做强制云、不做插件市场、不做第二套知识库 |

### 必学（至少 3 条）

1. **单面写作默认态**：所见即所得 = 编辑面本身；不要再套一层「预览」才能安心（Typora）。  
2. **自动保存体感**：打字即安心；「保存」降为确认/快捷键，而非主路径焦虑按钮（Notion / Obsidian）。  
3. **Chrome 让路给正文**：少顶部说明墙、少双重模式选择；格式控件紧凑，选中才强调（三家共性）。  
4. （加分）**粘贴/拖入图片**自然进正文；MD 进来变可编辑排版，而不是「先预览再编辑」。

### 明确不学 / 否决

1. Obsidian 插件生态 / 双链图谱 / 多窗格 IDE 感（超边，会中速记用不上）。  
2. Notion 云协作、权限、数据库块（与本地优先、套件定位冲突）。  
3. 继续用「模式下拉 + 编辑/预览 + 长 Hint」三层同时教育用户（当前难受主因）。  
4. 为追 Typora 重做成独立 Markdown IDE（违背办公套件「装一个就够」）。

### 可超越（相对独立 App）

- 与 **剪贴板历史 / 截图** 同壳互喂，少一次 Alt-Tab。  
- **简约纯文本 ↔ 所见即所得** 同大纲、同热键，服务「会中先记后排」而非强迫人人学 MD。  
- 主题跟 TOA 壳一致，不另装第二套皮肤心智。

## 3.4 当前 TOA3 UI vs Top3：为何「特别难受」（推断）

对照截图（模式「多功能·所见即所得」+ 编辑/预览 + H1…工具栏 + 长说明 + 显式保存）与实现（`modules/quick_notepad/quick_notepad_page.py` + `rich_body.py`）：

| # | 痛点 | 用户感知 | Top3 对照 |
|---|------|----------|-----------|
| 1 | **双重模式**：顶栏「简约/多功能」+ 正文「编辑/预览」 | 已经「所见即所得」还要选编辑或预览 → 不知该信哪一层 | Typora 无此开关；Notion 无「预览才能看排版」 |
| 2 | **预览与 WYSIWYG 语义打架** | 编辑态已是排版结果，预览像重复功能 | 真 WYSIWYG 不需要第二只读面作默认主路径 |
| 3 | **显式「保存」作主按钮** | 会中怕丢，却又觉得「不是现代笔记」 | 三家默认自动落盘体感 |
| 4 | **说明长句霸状态区** | 「选中文字点工具栏…」等于承认 UI 不自解释 | 头部用空状态/tooltip，不把说明书钉在编辑器下 |
| 5 | **工具栏像表单按钮墙**（H1 H2 B I 文字块） | 粗、占位、无「当前格式」回显 | Notion/Typora：图标+选区高亮，正文视觉优先 |
| 6 | **写作面被壳层文案包围**（页头 Outline 说明 + 快捷键 Hint + 大纲 Hint） | 还没打字已被教程淹没 | 头部：焦点在空白写作区 |
| 7 | **存盘 HTML（`<!--toa-html-->`）** | 导入 MD 尚可，但「多功能」不像 MD 工具；往外拷格式不稳定风险 | Typora/Obsidian 以 MD 为真源；Notion 接受专有块但自动保存体验好 |
| 8 | **模式切换用 `toPlainText` 降级** | 多功能→简约可能甩格式，不敢切 | 切换应可预期、可逆或强提示 |

> 结论：难受主要来自 **心智模型叠床架屋 + 非沉浸写作面 + 手动保存焦虑**，不是「缺更多按钮」。

## 3.5 三个独到之处（经主理人论证）

| # | 独到主张（一句话） | 用户可感知价值 | 可测验收 | 论证结论 |
|---|--------------------|----------------|----------|----------|
| 1 | **套件投喂链**：剪贴板历史项 / 截图结果 **一键落入当前记事所见即所得**（文本直接进光标；图片进正文），无需另开 Typora/Notion | 会中少切窗；「记」与「抓」在同一套件完成 | 从剪贴板历史或截图链路到记事 → 当前条可见对应文本或图；≤2 次点击或一条快捷键 | ✅ 主理人确认 |
| 2 | **会中双轨同大纲**：同一笔记列表下 **纯文本秒记 ↔ 所见即所得** 一键切换且 **正文不丢**（格式降级须可预期提示）；默认进入「打开即写」单面，不默认甩「编辑\|预览」 | 先狂记后排版，不必换 App；也不被模式教育打断 | 简约↔多功能往返后纯文本内容仍在；多功能默认仅一块可打字面；无必点「预览」才能看排版 | ✅ 主理人确认 |
| 3 | **本地可携出**：导入 `.md` → 立即成可编辑排版；**复制正文带富文本**（HTML）便于贴回 Word/邮件；全程本地、跟 TOA 主题，不强制云账号 | 相对 Notion 无登录墙；相对独立 MD 编辑器少装一个软件且主题统一 | 导入样例 MD 后标题/列表/图可改；复制后粘贴到外部富文本区格式仍在；断网可用 | ✅ 主理人确认 |

## 4. 技术方案

| 项 | 结论 |
|----|------|
| 选定栈 / 库 | `QTextEdit` 富文本 + `rich_body`；去掉编辑\|预览叠层，仅简约/多功能双轨 |
| 否决项及原因 | 引入 Electron/Web 编辑器整页；默认联网；Obsidian 式插件；Notion 式云库 |
| 架构落点 | `modules/quick_notepad/*`；剪贴板历史「送入记事」；截图完成进剪贴板后可由记事「从剪贴板」落图；存储仍 `storage_paths` |
| 性能约束 | 热键/进页禁止同步联网；大图继续限宽；自动保存 debounce ≈800ms |
| 品质验收 | 见 §3.5 + 附录 B 五项修复 |
| 如何兑现 §3.5 | #1 系统剪贴板图文 + 历史投喂 + 送入记事；#2 单面写作 + 自动保存 + 模式切换保正文；#3 导入 MD + HTML 复制 |

## 附录 B · 研究隐含的 Top 修复方向（供论证后排期 · 非实现清单授权）

1. 多功能模式下移除或降级「编辑/预览」双按钮（预览改导出/只读查看，勿与 WYSIWYG 并列）。  
2. 默认自动保存（debounce）+ 状态栏「已保存」；主按钮不再制造「不按就丢」焦虑。  
3. 格式工具栏改紧凑图标 + 选区格式态；去掉编辑器下方说明书长句。  
4. 压缩页头/大纲教学文案，把垂直空间还给写作面。  
5. 强化「从剪贴板（含图）」与套件互喂，使投喂链可感知（对齐草案 #1）。
