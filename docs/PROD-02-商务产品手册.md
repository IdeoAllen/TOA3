## 一、一页纸摘要（可直接用于开场）

**运营宝（TOA）** 是面向办公室人员的 **桌面办公套件**：安装一套软件，即集成剪贴板、截图、记事、目录与文件处理、桌面浏览，以及培训业务材料生成与检核等能力，减少「到处装、到处切」的散装工具成本。

| 维度 | 主张 |
|------|------|
| **给谁** | 培训运营、教务、行政与通用白领；也适合需要统一桌面效率工具的团队采购 |
| **解决什么** | 多工具切换、学习与维护成本高；交付材料手工拼凑；结果难追溯 |
| **怎么交付** | Windows 本机安装；本地优先、可离线办事；授权码激活付费能力 |
| **和散装软件比** | 一站集成 + 统一体验；单项能力对标品类头部主路径，不以「凑合集成」交差 |
| **和通用效率套件比** | 多一段 **培训运营垂直链**（排课材料 → 桌卡简历 → 水印照片 → 目录检核交付） |
| **商业结构** | **免费钩子**（基础能力常驻）+ **高级功能付费**（体验/方案授权）；与 DMS（专业高门槛可售系统）并行、不强绑 |

**一句话成交逻辑：**  
少装几个软件、少切几下窗口、交付材料更快更规范——装完愿意天天用，才算值。

## 二、产品概述

### 2.1 我们是什么

运营宝是运行在 **Windows 桌面** 上的办公效率平台：

- **办公层**：剪贴板历史、截图标注、快速记事、四象限任务、大模型润色、网页工作台等  
- **资料层**：批量建夹、目录透视、PDF、打包归档、批量重命名、文档合成等  
- **图像层**：去水印、扫描件、图转文件、照片提取、媒体工坊等  
- **引擎层**：编码智能体、流程图、设计编辑器等开源能力宿主  
- **业务层**：培训运营场景的桌卡、日程、水印照片、交付报告等  

气质是 **一站式办公效率**；培训业务是 **加分能力**，不是「只会培训系统」。

### 2.2 我们不是什么

| 不是 | 说明 |
|------|------|
| 不是网页门户凑菜单 | 核心办事在桌面客户端完成 |
| 不是功能导航站 | 每个能力要能独立把事办完 |
| 不是必须绑定业务中台才能用 | 与 DMS 为并行可售产品、**无强绑定**；TOA 授权不强制 DMS 在线 |
| 不是百宝箱堆砌 | 宁少勿滥；不做「半成品堆满菜单」 |

### 2.3 产品承诺（对外可复述）

1. **打开就能用，用完不想换** —— 降低工具切换与学习成本。  
2. **少点一下，多干一件事** —— 热键、托盘、覆盖层支持高频动作。  
3. **每个能力对标同类工具** —— 集成到一处，但不能比同类差。  
4. **本地优先、可离线** —— 日常结果落在本机，可追溯、可打开所在目录。  
5. **统一专业体验** —— 一套界面风格，而不是插件拼盘观感。  
6. **工具好用，结果是用户自己的** —— 例如记事：组件/工具帮排版，模板只给空白骨架，不堆预制范文。  
7. **记事本：编辑 + 源码 + 预览** —— **编辑**打开即成品文档版式；**源码**直接改 Markdown；**预览**只读纸面；底栏效率指南；落盘仍为同一份 Markdown；组件库承载标记全集；工具栏同源。详情见 PROD-01 §0.5.1。

## 三、商务价值与采购理由

### 3.1 客户痛点（谈判共鸣点）

| 痛点 | 现状常见做法 | 带来的成本 |
|------|----------------|------------|
| 工具散装 | 截图、剪贴板、建夹、PDF 各买/各装一套 | 采购、安装、升级、快捷键冲突 |
| 培训交付靠手工 | Excel + 复制粘贴 + 多人约定目录 | 出错、返工、交接成本高 |
| 结果难找 | 文件散落桌面与各软件缓存 | 复盘与审计困难 |
| 风格不统一 | 各工具界面与操作习惯不同 | 培训新人成本高 |

### 3.2 价值主张（三角）

```
            效率
         （少切换）
              /\
             /  \
            /    \
     体验 -------- 可控
  （统一专业）  （本地·可离线·可追溯）
```

| 价值 | 商务话术要点 |
|------|----------------|
| **效率** | 一套入口覆盖高频办公与交付动作；热键唤起，不必先找窗口 |
| **体验** | 统一壳层与交互，降低团队培训与支持负担 |
| **可控** | 数据在客户本机；弱网/离线仍可办日常事；授权与方案可管理 |

### 3.3 可量化的谈判角度（示例，可按客户改写）

- **工具合并**：若团队人均装 3～5 个小工具，合并为 1 个套件 → 安装点与升级面下降。  
- **交付提速**：桌卡/水印照片/目录检核由向导完成 → 减少重复表格操作与目录差错。  
- **支持成本**：统一热键与界面 → 减少「这个软件怎么用」类工单。  

> 具体 ROI 数字建议在售前按客户人数、班次规模、现有工具清单测算后写入商务方案，不在本手册写死承诺值。

### 3.4 成功标准（客户侧可验收）

商务与试用验收建议用下面问题，而不是「菜单有多少项」：

1. 常用一周后，是否愿意减少或停用独立截图/剪贴板类软件？  
2. 截图、剪贴板、记事等主路径是否顺手、稳定？  
3. 培训交付（桌卡、材料、检核）是否比纯手工明显更快、更少返工？  
4. 热键/浮层是否默认不打断其它工作，做完能立刻回到原上下文？  
5. 断网或弱网时，日常高频工具是否仍能办事？

## 四、适用对象与典型场景

### 4.1 目标用户

| 角色 | 核心诉求 | 优先能力区 |
|------|----------|------------|
| 通用白领 / 行政 | 截图、剪贴板、记事、文件整理 | 办公、文件、图片 |
| 教务 / 培训运营 | 开班材料、桌卡、水印、交付质检 | 业务 + 文件 |
| 团队负责人 / IT | 统一工具、可控授权、少装机 | 全套件 + 授权方案 |
| 需要扩展能力的团队 | 自建业务页、智能体协助 | 引擎、扩展 |

### 4.2 典型场景故事（商务演示可用）

**场景 A · 会议与协作**  
开会截图标注 → 进剪贴板历史反复粘贴 → 快速记事留会中草稿 → 大模型助手润色通知。

**场景 B · 开班准备**  
粘贴学员名单批量建文件夹 → 桌卡批量生成 → 班级照片按规则加水印 → 目录透视核对结构。

**场景 C · 交付验收**  
材料打包归档 → 生成交付报告 → PDF 合并拆分抽页 → 本机目录可追溯。

**场景 D · 个人效率**  
四象限看今日轻重缓急 → 热键唤起剪贴板/截图 → 网页工作台固定常用文档站点。

## 五、产品结构（用户怎么理解）

### 5.1 三级导航（商务讲解用）

| 层级 | 用户理解 | 界面位置 |
|------|----------|----------|
| 一级 · 子模块 | 我进哪个工作区 | 顶栏：首页 / 办公 / 图片 / 文件 / 引擎 / 业务 / 系统 |
| 二级 · 功能 | 用哪个工具 | 左侧栏 |
| 三级 · 任务页 | 办这一件事 | 主内容区 |

### 5.2 系统介入（卖点：不必总开着主窗）

| 方式 | 价值 |
|------|------|
| 全局热键 | 截图、快贴、记事等一键唤起 |
| 系统托盘 | 主窗可收起，需要时再召唤 |
| 覆盖层 | 全屏截图/快贴；完成或 Esc 即退 |
| 命令面板（Ctrl+K） | 关键字直达功能 |

原则：**默认不打断其它应用；一次一事；键位可关可改。**

### 5.3 数据与结果

生成、导出、历史默认落在本机；完成时常提供「打开所在目录」。  
适合对外强调：**数据在客户侧、结果可找、可离线办事。**

## 七、差异化与竞争对照（商务话术）

### 7.1 相对「散装独立软件」

| 对比点 | 散装工具 | 运营宝 |
|--------|----------|--------|
| 安装与升级 | 多套软件 | 一套客户端 |
| 学习成本 | 多套交互 | 统一壳层 |
| 热键与介入 | 易冲突、难统一 | 可配置的统一热键策略 |
| 结果位置 | 分散 | 本机可追溯 + 打开目录 |
| 采购 | 多次采购/免费拼凑 | 方案化授权 |

**话术：** 我们不是再做一个「第 N 个小工具」，而是把高频工具收成 **愿意天天用的一处**。

### 7.2 相对「纯办公效率合集」

| 对比点 | 通用效率合集 | 运营宝 |
|--------|--------------|--------|
| 白领小工具 | 通常具备 | 具备，且对标头部主路径 |
| 培训交付链 | 通常没有 | **桌卡、日程、水印照片、目录检核、交付报告** |
| 扩展与智能体 | 少见或另购 | 壳内引擎 + 扩展能力 |

**话术：** 白领能当效率套件用；培训团队多一段 **交付闭环**，这是加分项而不是唯一叙事。

### 7.3 产品纪律（可当作信任状）

- **宁少勿滥**：不做半成品堆菜单。  
- **对标头部**：关键能力对照品类头部主路径设计。  
- **可感知差异**：每个重点能力强调「用户能感觉到的不同」，而不是参数表堆砌。

## 八、授权与商业模式

### 8.1 版本结构（对外口径）

| 类型 | 含义 | 到期后 |
|------|------|--------|
| **单机基础使用** | 安装后可使用标记为「基础」的能力（如剪贴板、截图、记事等日常工具）；可离线 | 基础能力持续可用（以产品规则为准） |
| **体验授权** | 运营侧签发体验码；期内按体验方案开放能力 | 体验收回；可再申请体验或购买 |
| **付费授权** | 订单履约签发付费码；按产品方案开放专业/业务等能力 | **基础能力保留**；方案内付费模块收回，需续费 |

### 8.2 产品方案（SKU）

当前可售主方案为 **体验版/全功能方案口径**（方案内可含全部付费模块；具体以运营台「产品方案」与订单为准）。  

- 默认参考有效期：**365 天**（订单可另定）  
- **目录价与折扣**：以当期商务报价单为准（本手册不锁定价格）  
- 亦可按商务约定挂接扩展开发等能力包  

### 8.3 激活与履约

1. 客户下单 / 申请体验 → 运营台签发授权码  
2. 客户在终端激活 → 本机写入授权状态  
3. 付费履约：**一订单一码**，便于对账与续费  

### 8.4 与 DMS 的关系（双产品并行 · 2026-09-07 裁定）

| 产品 | 定位 | 收费 |
|------|------|------|
| **运营宝（TOA）+ 腾讯文档轻量轨** | 桌面办公与课前材料；轻量、灵活、可扩展 | **免费钩子**（白领日活等）+ **高级功能付费**（材料全链路、培训交付看板等） |
| **DMS** | **专业**运营培训系统（完善、高端） | **可售**；门槛高；**不是**免费钩子 |

- 两套 **并行可售**，可单买或组合买；组合是商务打包，**不是**产品耦合。  
- TOA **不硬依赖** DMS 在线；DMS **不**提供 TOA SKU / 不做 TOA 授权账本。  
- 协作常见路径：TOA 本机出材料 →（可选）人工上传 DMS；无自动同步强制。  

详见 `docs/architecture/ARCH-04-授权与单机联网.md` v3。

### 8.5 商务边界建议（谈判时可用）

- TOA 授权按 **设备/码** 管理；批量采购可谈多码与统一续费。  
- DMS 报价与履约走 DMS 产品侧，**勿**与 TOA 授权码混开成「一套账本」。  
- 二次开发、现场培训、专属模板定制：建议单列服务项，不默认含在软件授权内。  
- 云端大模型、商用 OCR、生图算力等：若走第三方，费用与密钥由客户侧配置或另计。

## 十一、商务常见问题（FAQ）

**Q1：必须联网才能用吗？**  
A：日常基础办事以本地为主，可离线。激活授权、部分云端能力、在线更新需要网络。

**Q2：和钉钉/企微/腾讯文档/DMS 什么关系？**  
A：腾讯文档可作轻量日常协作面（网页工作台或导入表）；钉钉/企微深度对接按版本开放。DMS 是并行的**专业运营培训系统**（可另购、门槛较高），与 TOA **不强绑**——不是「没装 DMS / 没装钉钉就不能用 TOA」。

**Q3：数据会上传你们服务器吗？**  
A：核心办公与生成结果默认在客户本机。涉及云授权校验、客户自行配置的第三方大模型/OCR 等，按对应服务条款与客户配置发生；商务材料可按需补充数据说明。

**Q4：体验到期后软件是不是全废？**  
A：体验到期按体验规则收回期内开放能力。付费到期后，**基础能力仍可用**，方案内付费模块需续费。具体以授权规则与激活状态为准。

**Q5：能否只买培训业务、不要办公工具？**  
A：产品以套件形态交付；具体模块开关与方案组合以当期可售 SKU 与商务约定为准。

**Q6：能否定制我们单位的专属流程？**  
A：可通过扩展机制与智能体协助做本机扩展；大型定制建议单列项目，不默认含在标准授权。

**Q7：价格多少？**  
A：以正式报价单为准。方案参考有效期可为一年，折扣、席位/授权码数量、服务捆绑在商务环节确定。

**Q8：是否替代 Office / WPS？**  
A：不替代完整办公套件。运营宝补的是 **效率工具 + 培训交付工具链**，与 Office/WPS 并用。

## 十二、谈判一页卡（可打印）

**产品：** 运营宝（TOA）· 桌面办公套件  

**卖什么：** 免费钩子留住日活 + 高级能力（含培训材料全链路）付费；本地优先；统一体验。可与 DMS（专业系统）组合采购，不强绑。

**怎么验：** 愿不愿少用独立小工具；交付链是否更快更稳；热键是否跟手且不扰人。
