## 3. 取长补短矩阵

| 维度 | Docker Desktop | JetBrains Toolbox | LM Studio | **TOA 采纳** |
|------|----------------|-------------------|-----------|--------------|
| 核心流程 | 启停引擎 → 干活 | 目录选工具 → 装/更新 | 选模型 → 本地聊 | **目录选引擎 → 六件套 → 浏览器干活** |
| 交互细节 | 状态明确；修麻烦时常「重装」 | 卡片列表 + 统一更新 | 主 CTA 清晰 | **卡片目录 + 选中展开 Host 壳；主 CTA=浏览器打开** |
| 性能 / 延迟 | 启动重 | 轻 | 中 | **进页不探网；状态异步；日志懒开** |
| 能力深度 | 容器全家桶 | IDE 生态 | 模型推理 | **只做生命周期 Host，不重做 Agent/Comfy UI** |
| 明显短板（避开） | 故障黑盒、重装劝退 | 与办公传送门无关 | 无剪贴板/任务投喂 | **人话修复 + 传送门投喂；不做费用** |

### 必学（至少 3 条）

1. **一眼状态**：未装 / 已停 / 运行中 / 异常，灯色与文案固定，不发明第五态糊弄用户。  
2. **目录与生命周期同构**：装、更新、卸在同一套卡片范式（Toolbox）。  
3. **主路径去干活**：运行后第一动作是打开工作面（浏览器），不是钻设置。

### 明确不学 / 否决

1. 默认 WebEngine 重嵌冲「浏览器同等专业感」。  
2. 费用 / 账单 / 用量大盘（Doc 33 §6）。  
3. 改写现有引擎业务页「顺便加按钮」（破坏开闭、回归风险）。  
4. 任意 URL 脚本市场（仅可信收录清单）。

### 4.1 停做 · 换技术方案（主理人 2026-09-07）

**现状判决**：Hub 是目录壳；自家 Harness 仍报「缺少核心 Web 组件」，安装失败——**不能帮客户，先不要做**。侧栏 `show: false`。

**新方案门槛（满足才重开管家）**：

| 原则 | 含义 |
|------|------|
| 无感 | 用户 ≤1 次确认；不读终端；失败由软件自愈或人话一步修好 |
| 不演 UI | 禁止再做「装/卸/修」按钮墙而底层仍坏 |
| 预置优先 | 官方/随包运行时、或一次性安装包；少现场 `npm/git/junction` |
| Agent 可代劳 | 复杂环境允许「一键交给 Agent 装好再绿灯」；TOA 只呈就绪态 |

**候选技术路线（择一，立项后再写码）**：

1. **预置运行时包**：随 TOA 或独立 Offline Bundle 下发已链好的 dsh/web 组件，点启动即开浏览器  
2. **官方安装器**：跳转/静默跑官方 Setup，TOA 只探测就绪 + 打开工作台  
3. **Agent 代装**：编码智能体在浏览器完成安装修复，桌面只显示「就绪 / 未就绪」与打开  

原 §4.1 HostRuntime / Git 导入向导：**冻结**，直到上述门槛达成。
