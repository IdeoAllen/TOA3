# 11 · 产品核心规范

TOA3 的六项核心要求及落地方式。

## 1. 风格统一 · 专业

| 要求 | 落地 |
|------|------|
| 全局主题 | `config/themes` → QSS，禁止页面硬编码色 |
| 控件一致 | `widgets/` + `modules/gallery` 验收 |
| 字号间距 | `widgets/metrics.py` + `config/ui_spec.yml` page 边距 |
| 窗口一致 | `config/ui_spec.yml` + `core/ui_spec.py` |
| 图标清晰 | SVG + HiDPI；禁止模糊/锯齿；见 `docs/standards/控件库规范.md` |

## 2. 功能简捷实用

- 一模块一屏主任务，次要操作进设置或工具栏
- 默认示例数据走 `assets/samples`，减少空页
- 状态反馈走壳状态栏 `report_status`，不用弹窗刷屏
- **小白路径**：拿来即用、极简步骤，享受便捷与高效；销售叙事为一站式
- **双门槛探索**：技术能力 / 电脑条件有余时，软件引导探索增强；探索须一件安装、配置 ≤2 步，步步有引导；未探索不影响主任务

## 3. 架构清晰 · 可扩展

```
modules → widgets/ui → app/core → services → config
```

- 新模块：`BasePage` + `storage.yml` 登记 + `MIGRATED_MODULES`
- 新三方：`services/integrations` 登记 + `integrations.yml`

## 4. 安全可靠

- 授权：license + DMS（`services/integrations/dms_license`）
- 敏感配置：`license.json` gitignore；生产关闭 `skip_login`
- 路径：`storage_paths`，不写系统目录外的任意路径
- 日志：`error_handler` 记录 detail，用户只见 `user_message`

## 5. 三方对接统一规划

| 系统 | 配置 | 代码入口 |
|------|------|----------|
| DMS License | `integrations.yml` + `license.dms_base_url` | `get_client("dms")` |
| 邮件 | `integrations.yml` + `email.*` | 待 `email_client` |
| OCR | `integrations.yml` + `ocr.*` | 待 `ocr_client` |

**禁止**模块内直接 `urllib` / `requests` 调外部 URL；经 `IntegrationClient` 子类。

## 6. 异常统一处理

| 层级 | 入口 |
|------|------|
| 页面 | `BasePage.run_safe` / `handle_error` |
| 弹窗 | `BaseDialog.run_safe` |
| 服务 | 抛 `TOAError` 子类，带 `user_message` |
| 全局 | `install_qt_exception_hook()` 记未捕获异常 |

**禁止**业务里裸 `QMessageBox`（登录等壳层可用 `report_error`）。

### 生成 / 导出完成提示（硬门禁）

凡产出文件或目录的功能，完成后必须：

- `core.user_messages.show_saved(parent, text, path)` — **绿色「完成」**对话框
- 带 **「打开所在目录」**（`path` 为文件或输出目录）
- **禁止**用蓝色 `show_info` 冒充完成

无文件产出的操作（复制剪贴板、仅改配置）可用 `show_success` / `show_info`。

## 7. 窗口规格统一

见 `config/ui_spec.yml`：

- `shell`：主窗最小/默认尺寸、顶栏 48、侧栏 200
- `dialogs.login|small|medium|large`：弹窗规格
- `page.margin/spacing`：业务页边距
- `message.*_title`：提示框标题

代码：`apply_shell_spec`、`apply_dialog_spec`、`apply_page_layout`。
